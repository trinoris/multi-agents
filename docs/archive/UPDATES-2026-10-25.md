# Protocol Updates — 2026-10-25T10:46

## Summary

Critical improvements to the multi-agent coordination protocol based on operational analysis. All changes strengthen the protocol's ability to prevent silent failures and improve agent awareness of system state.

## Changes by spec

### Spec 01 (coordination-protocol.md)

1. **Incident visibility on acquire** — Added mandatory step 1 to acquisition: check `incidents/` for recent events in the target scope (< 1 hour). Prevents re-acquiring after eviction without understanding what happened.

2. **Git scope pre-check rule** — Before acquiring `git` for branch-mutating operations (`checkout`, `switch`, `merge`, `rebase`, `reset`), must `ls coordination/locks/` and abort if any peer lock with a live lease exists. This is the highest-risk operation in the protocol; the check is now explicit and enforceable.

3. **Heartbeat for long operations** — Extended "Hold and renew" to specify: long operations (>5 min) that cannot checkpoint should write `coordination/heartbeat/<agent>.json` every 2 minutes with `{ agent, at, scope }`. Helps distinguish "slow" from "dead."

4. **Heartbeat-aware contention logic** — When evaluating an expired lease, check for fresh heartbeat (< 3 min). If present, wait one additional grace period before breaking. Prevents breaking locks on slow-but-alive agents.

5. **Enhanced heartbeat section** — Clarified that heartbeat is advisory evidence of liveness, not a lease extension. Fresh heartbeat defers breakability; stale/missing heartbeat does not override a live lease.

6. **Archive index in layout** — Added `archive/INDEX.md` to directory structure, documenting its purpose (one-line entries per archived note).

### Spec 02 (lock-mechanism.md)

7. **Worked example of ABA problem** — Added detailed timeline (T+00:00 through T+06:05) showing how Agent A can lose a lock, have it re-acquired by Agent B, and still see the lock directory exactly as before. Makes the re-verify rule's purpose explicit and visceral.

### Spec 03 (handoff-format.md)

8. **Archive index maintenance** — Added rule: when moving a note to `archive/`, append a one-line entry to `archive/INDEX.md` with format `- <filename> — [scopes] — <outcome>`. Makes history searchable without `grep -r`.

9. **Resolved open question** — Marked archive indexing as resolved (was pending decision between `git log` and explicit index; explicit index chosen).

## Rationale

### Why these changes matter

**Incident visibility (changes 1, 10, 12)** — Without this, an agent evicted by a broken lock wakes up later, re-acquires the scope, and has no idea its previous work was interrupted. The incident file exists but is never read. Now it's checked on every acquire.

**Git scope pre-check (changes 2, 10, 12)** — Switching branches while a peer holds a lock is the protocol's only operation that is *actively destructive* (all other violations are "merely" silent data loss). This makes it enforceable rather than advisory.

**Heartbeat mechanism (changes 3, 4, 5, 12)** — The 15-minute lease with 5-minute renewal assumes operations checkpoint frequently. Long operations (deep analysis, waiting for user input, slow build) can't meet that. Heartbeat is lightweight (no JSON rewrite) and separates "alive" from "actively working."

**ABA worked example (change 7)** — The ABA problem is subtle and the re-verify rule seems paranoid until you see the timeline. The worked example makes it obvious why presence ≠ ownership.

**Archive index (changes 6, 8, 9)** — Without it, "what happened to `engine` last month?" means reading every file in `archive/`. With 50+ handoffs over time, that's unmaintainable. The index makes history searchable.

**Test specifications (changes 10, 11)** — MA-T06..T09, T11 were placeholders. Now they have explicit acceptance criteria, which makes implementation unambiguous.

## Backward compatibility

All changes are **additions or clarifications**, not breaking changes:

- Existing lock acquisition still works; incident check is a new first step
- Heartbeat is optional for operations that can renew leases normally
- Archive index is append-only; existing archives without an index are valid (start one now)
- All new tests validate behavior already described in the specs, now made explicit

Consuming repos that adopted the protocol before these changes should:
1. Re-read spec 01 sections on Acquire, Git scope, Heartbeat
2. Add incident checks to their lock acquisition logic
3. Create `archive/INDEX.md` and backfill recent entries (optional but recommended)
4. Implement git pre-check before branch operations (critical)
